# Guardian CFO: REST API Reference Documentation

**Base URL:** `http://127.0.0.1:8000/api/v1`  
**Authentication:** HTTP Bearer Token (`Authorization: Bearer <jwt_access_token>`)  
**Data Format:** `application/json` (UTF-8)  
**OpenAPI Specification:** Available interactively at `/docs` (Swagger UI) and `/redoc`  

---

## 1. Authentication & Tenant Endpoints

### `POST /auth/register`
Creates a new user and automatically provisions an isolated business tenant.
- **Status:** `201 Created`
- **Request Body:**
```json
{
  "email": "cfo@company.com",
  "password": "SecurePassword123!",
  "full_name": "Jordan Smith",
  "business_name": "Apex Innovations LLC",
  "currency": "USD"
}
```
- **Response:**
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsIn...",
  "token_type": "bearer",
  "user": {
    "id": 1,
    "email": "cfo@company.com",
    "full_name": "Jordan Smith",
    "role": "OWNER"
  },
  "business": {
    "id": 1,
    "name": "Apex Innovations LLC",
    "currency": "USD",
    "total_balance": 0.0
  }
}
```

### `POST /auth/login`
Authenticates an existing user and returns a scoped JWT token.
- **Status:** `200 OK`
- **Request Body:**
```json
{
  "email": "cfo@company.com",
  "password": "SecurePassword123!"
}
```

### `POST /auth/demo-login`
Initializes a zero-friction demo session with pre-seeded multi-month data for **Acme Autonomous Corp**.
- **Status:** `200 OK`
- **Response:** Returns standard `TokenResponse` with demo tenant credentials.

### `GET /auth/me`
Retrieves current authenticated user profile and business settings.
- **Status:** `200 OK` (Requires Bearer Token)

## 2. Financial Analytics Endpoints

All financial metrics are computed deterministically in Python using verified database records.

### `GET /analytics/summary?period=current_month`
Retrieves treasury balance, total revenue, total expenses, net cash flow, and runway months.
- **Status:** `200 OK`
- **Response:**
```json
{
  "period": "current_month",
  "total_revenue": 18750.0,
  "total_expenses": 17445.0,
  "net_cash_flow": 1305.0,
  "cash_flow_margin_pct": 6.96,
  "revenue_growth_pct": 10.29,
  "expense_change_pct": 306.64,
  "treasury_balance": 137350.0,
  "runway_months": 7.8,
  "currency": "USD"
}
```

### `GET /analytics/trends?months=6`
Returns monthly aggregated revenue, expenses, and net cash flow across 6 historical periods.
- **Status:** `200 OK`

### `GET /analytics/categories`
Provides proportional percentage shares across all expense categories.
- **Status:** `200 OK`

### `GET /analytics/anomalies`
Detects unusual month-over-month category spending surges (> 35%).
- **Status:** `200 OK`

### `GET /analytics/recurring`
Identifies active recurring vendor obligations and calculates monthly/annual fixed overhead.
- **Status:** `200 OK`

## 5. Secure Payment Management & PayPal Endpoints

### `GET /payments/vendors`
Lists approved payees with trust scores and historical volume.
- **Status:** `200 OK`

### `POST /payments/drafts`
Creates a payment draft with server-side validation and idempotency deduplication.
- **Status:** `201 Created`
- **Request Body:**
```json
{
  "vendor_id": 2,
  "title": "AWS Cloud Hosting - Monthly",
  "amount": 420.0,
  "currency": "USD",
  "category": "Infrastructure",
  "purpose": "Monthly cloud infrastructure hosting per contractual rate",
  "invoice_number": "INV-AWS-2026-904",
  "idempotency_key": "IDEM-KEY-90c141f344"
}
```
- **Response:** Returns rich `PaymentDraftResponse` with inline `risk_assessment` and `policy_eligibility`.

### `PUT /payments/drafts/{id}`
Updates draft details. **Security Invariant:** Modifying core commercial fields (`amount`, `vendor_id`, `purpose`) immediately revokes prior approval and resets status to `REVIEW_REQUIRED`.
- **Status:** `200 OK`

### `POST /payments/drafts/{id}/approve`
Explicitly authorizes a payment draft and locks it with a SHA-256 `details_hash`.
- **Status:** `200 OK`
- **Request Body:**
```json
{
  "notes": "Verified against AWS billing statement. Approved."
}
```

### `POST /payments/drafts/{id}/reject`
Explicitly rejects a payment draft with a mandatory governance explanation.
- **Status:** `200 OK`

### `POST /payments/execute`
Initiates payment disbursement for an approved draft via PayPal Orders v2 or simulated provider.
- **Status:** `200 OK` (or `400` if draft is unapproved/tampered or PayPal unconfigured)
- **Request Body:**
```json
{
  "draft_id": 196,
  "payment_method": "PAYPAL_SANDBOX"
}
```
- **Response (with configured PayPal credentials):**
```json
{
  "transaction_id": 87,
  "draft_id": 196,
  "status": "PROVIDER_PENDING",
  "provider": "PAYPAL_SANDBOX",
  "provider_reference": "5O190127TNF0B6E9",
  "approval_url": "https://www.sandbox.paypal.com/checkoutnow?token=5O190127TNF0B6E9"
}
```

### `POST /payments/capture-order`
Captures an approved PayPal Orders v2 session and debits the treasury balance upon confirmation.
- **Status:** `200 OK`
- **Request Body:**
```json
{
  "transaction_id": 87,
  "paypal_order_id": "5O190127TNF0B6E9"
}
```

### `POST /notifications/read-all`

- **Status:** `200 OK`

## 7. PayPal Webhook Endpoints

### `POST /webhooks/paypal`
Receives inbound webhook notifications from PayPal Sandbox.
- **Headers Verified:**
  - `paypal-transmission-sig`
  - `paypal-cert-url`
  - `paypal-transmission-id`
  - `paypal-transmission-time`
- **Behavior:** Verifies asymmetric signature against PayPal verification procedures, discards unverified payloads with `HTTP 400`, deduplicates repeat `event_id` occurrences with `HTTP 200`, and reconciles `CHECKOUT.ORDER.APPROVED` and `PAYMENT.CAPTURE.COMPLETED`.
